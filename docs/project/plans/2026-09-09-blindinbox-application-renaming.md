# BlindInbox Application Renaming Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (\`- [ ]\`) syntax for tracking.

**Goal:** Rename the unreleased Flutter/NestJS application from Slow Dating to BlindInbox across all supported platforms, the API contract, and active documentation.

**Architecture:** This is a configuration and branding migration, not a behavior change. The Flutter Dart package and every platform launcher identity are made internally consistent, while the API exporter writes a renamed deterministic artifact. Existing Oracle schemas, REST endpoints, and security behavior remain unchanged.

**Tech Stack:** Flutter 3.47/Dart, Android Gradle/Kotlin, iOS Xcode project settings, web manifest, Windows CMake/Win32 resources, NestJS 11/TypeScript, Jest, GitHub Actions.

## Global Constraints

- Use \`BlindInbox\` for user-visible product text.
- Use \`blind_inbox\` for the Dart package and Windows executable name.
- Use Android namespace and application ID \`com.quan.blindinbox\`.
- Use iOS application bundle identifier \`com.quan.blindInbox\` and test bundle identifier \`com.quan.blindInbox.RunnerTests\`.
- Rename the generated contract to \`docs/openapi/blindinbox-v1.json\`.
- Do not change Oracle schemas, API routes, authentication rules, matching/chat scope, or GitHub repository URL.
- Existing installations of \`com.quan.slow_dating\` are intentionally not upgraded; Android will install BlindInbox as a new app.
